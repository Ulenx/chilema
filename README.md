# 我的菜单（个人菜谱 / 甜点管理 App）

一个纯本地运行的安卓 App，用来管理自己的家常菜与甜点：快速录入菜谱、收集视频教程、
让 AI 从文字 / 截图 / 网页链接里拆解原材料、管理冰箱里的食材与调料、选菜后自动生成购物清单、
记录每道菜做了几次并顺手扣掉冰箱库存、留存成品照片。

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 两列图片浏览 | 菜谱 / 甜点列表是两列封面网格，没封面时用菜名占位，一眼看出有什么菜 |
| 快速录入菜谱 | 表单录入菜名、分类、简介、做法步骤 |
| AI 解析原材料 | 粘贴菜谱文字，调通义千问自动提取「食材 + 用量 + 单位」 |
| 从截图生成菜谱 | 选一张菜谱截图，调通义千问多模态模型一次性还原菜名、步骤、食材 |
| 从网页链接导入 | 粘贴菜谱网页链接，自动抓正文并整理成菜谱 |
| 从别的 App 分享导入 | 在下厨房 / 小红书看到菜谱，直接「分享」到本应用，自动解析 |
| 视频教学链接 | 每个菜谱可挂多条视频链接，点击直接跳转播放 |
| 家常菜与甜点 | 同一个列表，顶部「全部 / 家常菜 / 甜点」一键切换；甜点额外带烘焙温度 / 时间 / 份量字段 |
| 选菜 + 购买清单 | 勾选多道菜，自动合并同名同单位食材并求和，生成可勾选、可分享的清单 |
| 冰箱库存 | 底部「食材」Tab 管理家里的食材与调料，记数量、图片、购买日期和保质期 |
| 小票 / 截图录入 | 拍小票或买菜 App 订单截图，AI 认出食材名和数量，分类与保质期自己填 |
| 临期提醒 | 过期日期距今 ≤3 天标橙、已过期标红，顶部提示卡一键筛出「临期 / 过期」 |
| 关联菜谱 | 库存条目可手动关联某道菜，购物时能看出这个食材是给哪道菜买的 |
| 购物对比库存 | 生成清单时自动对照冰箱：够用标「够了」、不够标「还差多少」、没有标「需补买」 |
| 做菜频率 | 详情页「我做了一次」一键记录，列表显示做过的次数，统计页有排行 |
| 做完自动扣库存 | 记录做菜时按菜谱用量扣减冰箱，扣之前弹明细确认框，可以逐条取消勾选 |
| 成品照片与封面 | 记录做菜时附上成品照片；事后也能给老记录补图 / 换图 / 删图，并可一键把某张设为菜谱封面 |
| 星级评分 | 每次做菜打 1–5 星，菜谱总分取**历次平均**（支持半星），列表卡片与详情页都能看到 |

数据全部保存在手机本地（Room / SQLite），不上传任何服务器。
只有使用 AI 解析功能时才会联网：把你粘贴的文字、选择的截图、或抓取到的网页正文
发送给通义千问。抓网页只发生在「从链接导入」这一步，且只抓你给的那一个链接。

## 技术栈

- Kotlin + Jetpack Compose（Material 3），单 Activity + Navigation Compose
- Room（本地数据库，5 张表：菜谱 / 菜谱食材 / 视频链接 / 做菜记录 / 冰箱库存）
- OkHttp + Gson（调用通义千问 DashScope 的 OpenAI 兼容接口，也用来抓菜谱网页）
- DataStore（保存 API Key）
- Coil（图片加载）
- MVVM：ViewModel + StateFlow + Repository，依赖注入用手写的轻量 `AppContainer`

网页抓取是手写的极简 HTML → 文本（`data/ai/WebPage.kt`），没有引入 Jsoup：
抓下来的内容只是喂给大模型看的，粗糙的正文对它够用，不值得为此多一个依赖。

## 构建与运行

### 方式一：用 Android Studio（推荐）

1. 打开 Android Studio，选择 **Open**，指向本项目根目录。
2. 首次打开时，Android Studio 会自动补全 `gradle/wrapper/gradle-wrapper.jar`
   并同步 Gradle 与依赖（需要联网）。如果提示缺少 Gradle wrapper，按提示接受即可。
3. 等待 Gradle Sync 完成。
4. 点击工具栏的 **Run ▶**，选择模拟器或已用 USB 连接并开启调试的真机。

> 本机的 Android SDK 路径已经写进 `local.properties`（`sdk.dir`）。
> 如果你的 SDK 装在其他位置，请修改该文件，或删除它让 Android Studio 重新生成。

### 方式二：命令行

用 Android Studio 自带的 JDK 直接调用缓存中的 Gradle 发行版，
**不需要** `gradle-wrapper.jar`（本机已实测通过）：

```bash
# 1) 设置 JAVA_HOME 为 Android Studio 自带的 JDK（路径按你的安装位置调整）
export JAVA_HOME="/g/Android Studio/jbr"          # Git Bash
# 或 cmd：set JAVA_HOME=G:\Android Studio\jbr

# 2) 用已缓存的 Gradle 直接构建（首次会下载依赖，需要联网）
"$HOME/.gradle/wrapper/dists/gradle-8.7-bin/*/gradle-8.7/bin/gradle" \
  -p "/path/to/caidan" :app:assembleDebug          # 换成你克隆下来的目录
```

如果你已经装好 JDK 17 且 wrapper jar 齐全，也可以用标准方式：

```bash
gradlew.bat :app:assembleDebug     # Windows
./gradlew :app:assembleDebug       # macOS / Linux
```

产物：`app/build/outputs/apk/debug/app-debug.apk`，可直接安装到手机。

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 首次使用：配置通义千问 API Key

AI 功能（解析食材、识别截图）需要通义千问的 API Key，不配置也能正常手动录入。

1. 打开 [阿里云百炼控制台](https://bailian.console.aliyun.com/)，登录后开通服务。
2. 在「API-KEY 管理」里创建一个 API Key（形如 `sk-xxxxxx`）。
3. 回到 App，进入底部 **设置** 页，把 Key 粘贴进去并保存。

设置页还可以切换模型：

- **文字解析模型**：`qwen-turbo`（最快最便宜）/ `qwen-plus`（默认，均衡）/ `qwen-max`（最强）
- **图片识别模型**：`qwen-vl-plus`（默认）/ `qwen-vl-max`（更强，用于识别复杂的菜谱截图和小票）

菜谱截图解析和冰箱的「小票识别 / 买菜截图」都走同一个图片识别模型；
文字解析、网页链接导入和分享导入都走文字识别模型。

API Key 只保存在本机，不会随任何数据上传。

## 菜谱导入的四条路

新建菜谱页顶部的「AI 快速录入」里有四个入口，按内容形态挑一个用：

| 入口 | 适合什么 |
| --- | --- |
| 粘贴菜谱文字 → AI 解析食材 | 已经复制到文字的内容，只提取食材清单 |
| 菜谱网页链接 → 从链接导入 | 有网址的菜谱页，自动抓正文并**整份**整理成菜谱 |
| 从截图生成 | 只有图片（截图、拍照的菜谱书） |
| 直接「分享」到本应用 | 在别的 App 里看到的菜谱，整份内容解析 |

分享导入的用法：在浏览器 / 下厨房 / 小红书等 App 里点「分享」，选择「我的菜单」。
App 会自动打开新建菜谱页并开始解析。如果分享文案是「标题 + 链接 + 复制此链接打开 App」
这类混合内容，App 会先挑出链接填进链接框，再决定是抓网页还是当正文解析。

> **抓不到正文是正常情况**：小红书这类前端渲染的站点，链接抓下来只有空壳。
> 这时会给出明确提示，改走「从截图生成」或自己复制文字粘贴即可，不会静默失败、
> 也不会编一份菜谱出来。短链接（t.cn 之类）能不能抓到取决于它跳到哪个页面。

## 做完一道菜会扣库存

点详情页的「我做了一次」，填完备注 / 照片确认后，App 会按这道菜的食材清单去冰箱里找能扣的：

- 匹配规则和「购物清单对比库存」是同一套：**同名、单位一致、没过期**。
- 有能扣的 → 弹一个明细确认框，逐条列出「这条用多少 · 库存多少 → 扣完剩多少」，
  默认全勾，不想扣的取消勾选即可。
- 没有能扣的 → 直接记一笔，提示里说明为什么没扣库存。
- **扣到 0 为止，不删条目**：用完的东西留在列表里显示「已用完」，比直接删掉可逆。
  已用完的条目也不再参与临期提醒（都吃完了还标红「快过期」是没意义的）。

同名但不可扣的库存也会列在确认框里并且禁用，附上原因（已过期 / 单位不一致 /
已经用完了 / 菜谱写的是「适量」），免得你看到「只扣了 2 项」不知道另外几条去哪了。

> **扣减不会撤销**：删掉那条做菜记录，扣掉的库存不会加回去。确认框就是最后一道关。
> 需要的话可以到冰箱里手动把数量改回来。

## 打分与成品记录

「我做了一次」的对话框里有 5 颗星，点第 N 颗就是 N 星。**星星默认是空的**（表示还没打分），
再点一下当前那颗可以清零 —— 没有这个动作就再也回不到「不打分」的状态了。

- **菜谱总分是历次平均**，不是最近一次。两次做菜打了 5 星和 2 星，这道菜就是 3.5 分。
  平均分可能出现小数，所以详情页的星星支持**半星**。
- 一次都没打过分的菜谱在详情页显示「还没评分」，列表卡片上则不显示星级那一格。
- 打分是可选的：0 星存进数据库时是 NULL，和「老记录从没打过分」是同一个状态。

**成品记录每一行都可以点开编辑**（想让入口更明显的话，没照片的行右边就有一个「加照片」按钮）：

| 能改什么 | 说明 |
| --- | --- |
| 备注 | 预填原来的内容，直接改 |
| 星级 | 补打、改分、清零都行 |
| 照片 | 给老记录**补图**、换一张、或者移除 |
| 设为封面 | 有照片时出现，勾上就把这张变成菜谱封面 |

编辑已有记录**不会**改「做过几次」和「最近一次时间」—— 改的是这条记录的内容，不是又做了一次。

> **两个已知的取舍**：
> 换照片或删照片时，旧图片文件会留在 `filesDir/photos/` 里不会被清掉（没有做垃圾回收）；
> 把某条记录的照片移除后，**菜谱封面不会跟着清空** —— 封面指向的是文件本身，文件还在就照常显示。
> 封面是独立的概念，这里不做联动。

## 冰箱管理怎么用

底部 **食材** Tab 分成「食材」和「调料」两大类：

- **食材**（肉类 / 蔬菜 / 水产 / 蛋奶 / 水果 / 主食 / 其他）记的是会过期的东西，有子分类；
  **调料** 只记名称数量，不再细分。
- 录入路径有三条：**手动填**、**小票识别**（拍纸质小票）、**买菜截图**（生鲜 App 订单截图）。
  后两条只用 AI 认「名称 + 数量 + 单位」，分类和保质期由你自己填 —— 识别结果会先列成草稿
  让你逐条核对、改数、删除，确认后再一次性保存。
- 每条可以**配一张图片**（食材本身、包装上的保质期都行），列表左侧显示缩略图。
  批量整理草稿时这一行会隐藏 —— 一批好几种东西共用一张图没有意义。
- **保质期**填「过期日期」（购买日期可选）。填写后：
  - 列表按 **已过期 → 临期 → 新鲜 → 没填** 排序，最该先吃的排最上面；
  - 过期日期距今 **≤ 3 天** 的标橙色、已经过去的标红色；
  - 顶部提示卡显示「临期 N · 过期 M」，点一下就能只看临期或只看过期。
- 阈值是代码里的常量 `NEAR_EXPIRY_DAYS`（`util/Expiry.kt`），默认 3 天，想改直接改这个值。
- 每条库存可以 **关联一道菜谱**，列表上会显示「关联：菜名」，方便知道这盒肉是买来做什么的。
- 生成购物清单时，App 会拿清单里的食材去比对冰箱：**同名同单位**且没过期的库存会直接抵扣，
  显示「冰箱已有 500 克，够了」「冰箱已有 1 个，还差 1 个」或「冰箱没有，需补买」。
  已过期的库存不算数，不会拿来抵掉你要买的东西。

> 提醒是**应用内**的（列表变色 + 顶部提示卡 + 筛选），不会发系统通知。
> 如果以后想要推送提醒，需要加通知权限和后台任务，属于后续增强。

## 数据说明

- 用户选择的图片会复制到 App 私有目录 `filesDir/photos/`，因此原图被删除也不影响显示。
  菜谱封面、成品照片、冰箱条目图片都是这个目录里的文件路径。
- 删除菜谱会级联删除其食材、视频链接和做菜记录；但**不会删掉冰箱库存**，
  只是把该库存的「关联菜谱」置空 —— 东西还在冰箱里，菜谱没了而已。
- 「设置 → 数据 → 清空全部菜谱数据」只会清空菜谱相关数据，冰箱库存不受影响。
- 数据库迁移都是纯加列 / 加表，老数据不丢：
  - **1 → 2**：新增 `fridge_items` 表；
  - **2 → 3**：`fridge_items` 加 `photoPath` 列；
  - **3 → 4**：`cook_records` 加 `rating` 列。这一列**可空且不带 DEFAULT**，老记录的
    `rating` 是 NULL，表示「没打过分」；迁移后 Room 会拿实际表结构和实体声明做比对，
    写成可空列才和实体上的 `val rating: Int?` 一致。
- 抓网页只发生在「从链接导入」这一步；抓到的网页正文会连同提示词一起发给通义千问，
  和粘贴文字走的是同一条路，不额外保存到本地。
